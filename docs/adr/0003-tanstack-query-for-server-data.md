# Server data in the web app goes through TanStack Query

Every page used to load its own data with a `useEffect`, `useState` and a "current" flag, and nothing was kept between visits: coming back to a page waited for the server again (1.7 to 3.2 seconds against the shared dev database). With Projects, Issues, Boards and Sprints coming, that boilerplate would be copied into dozens of pages, so server data in `apps/web` now goes through TanStack Query (`apps/web/src/api/queries.ts`). It was chosen over writing a cache by hand and over Zustand, which is for client state shared across components, not server data; none of that exists yet.

- **One cache for the app**, created by `createQueryClient()`. A page shows what it has cached at once and refreshes it in the background (stale time 0), so the skeleton is only for a first visit. Failed loads are not retried behind the page's back, and coming back to the window does not refetch. A refresh never throws away unsaved Grants (a dirty draft survives it; saving is refused if the Role changed), and a refresh that fails while older data is on screen says so.
- **Keys** live in `queryKeys`, from the general to the specific: `["roles"]` (list), `["roles", key]` (one Role), `["roles", key, "holders"]`, `["catalog"]`, `["audit", page, asOf]`, `["permissions", userId]`. A Role's pages share the `roles` prefix so one invalidation reaches all of them.
- **Changes invalidate, they don't patch.** After create, rename, save, reset, delete, give or take, call `useRolesChanged()` (or `useRoleDeleted()`): it refreshes the Roles, the audit log and the User's own permissions, and replaces the cached Role with the one the server returned (cancelling a refetch of it already under way, which would undo the change). New features add their own keys and a matching helper.
- **The cache belongs to the signed-in User.** `SessionProvider` empties it in `login`, `register` and `logout`, just before the User changes, so the next User's pages never start from it and never fetch twice.
- **The User's own permissions** are the exception to "stale time 0": they are kept for a minute, since every page and the navbar ask for them.
- **Paging** keeps the previous page on screen while the next loads (`keepPreviousData`).

Pages still decide how a failure looks: `loadFailure(query)` gives the status page to show, only while there is nothing cached to show.
