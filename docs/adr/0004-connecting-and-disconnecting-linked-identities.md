# Connecting and disconnecting Linked identities

Until now a Linked identity was only ever made as a side effect of signing in: "Continue with Google" on an email that already has a User links the Google login to that User (see the identity module spec, Linked identities). The Security page now lets a signed-in User connect and disconnect Google and GitHub, and two choices here would surprise a reader who only knows that rule.

- **A disconnect sticks.** Disconnecting deletes the Linked identity and records that the User disconnected that provider. While that mark exists, a sign-in with that provider is never linked to the User by email: on the User's email it is refused (`/login?error=disconnected`), and only Connect on the Security page links that provider again (and clears the mark). Without the mark, the next "Continue with Google" on the same email would quietly undo the disconnect, so a User could never cut off a Google account they no longer trust. We rejected keeping the row with a `disconnected_at`, because that leaves the provider account tied to this User forever. With the mark, the provider account belongs to nobody, as "disconnected" says. The mark is per provider, not per provider account, so no other Google account can be linked by email either.
- **Connect goes through a one-time ticket and needs a recent sign-in.** The OAuth start is a full page load and carries no Bearer token, so the web app first asks for a short-lived, single-use ticket bound to its Session and passes it on the page load. The handshake then links the provider account to that User instead of signing anyone in. We did not identify the User from the refresh cookie on that page load: that ties the link flow to the cookie's path and makes it easier to forge from another site. Connect also requires that the current Session started within the last 10 minutes. A password check would not work for Users who have none, and without that check a stolen access token could attach an attacker's Google account and keep access after the token expires. Every connect and disconnect also emails the User.
