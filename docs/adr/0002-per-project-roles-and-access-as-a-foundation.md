# Roles are assigned per project; every module depends on access, never the reverse

A User holds a Role either across all of Nimbus (a platform role, such as `platform_admin`) or in one project (a project role, exactly one per Member, such as Developer). We rejected the original plan of global permission groups with a "my projects" scope, because it cannot express the ordinary case of someone being an admin in one project and a viewer in another. Each Role is one kind or the other, and its Grants carry a Scope (`OWN` or `PROJECT` in project roles, `ALL` in platform roles), so row-level scopes still work inside each project.

`access` is a foundation, like `identity`: other modules call its public API (to check a permission, get a filter for a list, or give a Member their project role), and `access` never depends on them or listens to their events. It stores only project and User ids. We rejected letting `access` react to `projects`' Member events, because `projects` must also ask `access` for permissions, and the two-way dependency is a cycle that Spring Modulith's verification rejects. A direct call also lets a Member and their Role assignment be saved in one transaction.
