# The packaged Desktop app forwards API calls and keeps the cookies itself

The built web app calls relative `/api/...` paths. In a browser, and in `pnpm dev:desktop`, the Vite dev server forwards them to the API. The packaged Desktop app loads the built files from `app://nimbus`, where nothing answers `/api`, and the refresh cookie (`SameSite=Strict`, set by the API's origin) can't be carried by a page on another site. So the Electron main process answers `/api/*` on `app://` itself: it forwards the request to `NIMBUS_API_URL` (default `http://localhost:8080`) with Node's `fetch`, keeps the API's cookies in its own jar, sends them back where their `Path` says, and never shows `Set-Cookie` to the page. The API sees ordinary requests and needs no CORS settings or cookie changes.

- **The jar is the main process's.** It stores only what a first-party client needs (name, value, `Path`, `Secure`, expiry). A `Secure` cookie is sent only over https or to this computer, as a browser would. Cookies that last (the refresh cookie, 90 days) are saved between runs, encrypted with Electron's `safeStorage` (DPAPI, Keychain, libsecret) in the user data folder; where the system has no key store, nothing is written and the User signs in again each run. Sign-out clears it, because the API ends the cookie.
- **Google and GitHub sign-in can't finish in the packaged app, so their buttons are left out there.** The providers redirect the browser back to the API's `PUBLIC_URL` (`/api/auth/oauth2/callback/<provider>`), and the redirect URIs registered at Google and GitHub must be `http(s)` addresses. In the packaged app that would load another origin in the window, not `app://nimbus`, and the OAuth session cookie would be in a different jar. The preload script tells the page it is `packaged`, and the page then lists no providers (also no "Connect" on the Security page; a connected one can still be disconnected). In `pnpm dev:desktop`, which loads the dev server, they work as in a browser. They can come back when Nimbus has a hosted address that both the browser and the Desktop app use (a deep link such as `nimbus://` or a hosted web app loaded in the window).

## Considered Options

- **Let Chromium keep the cookies (`session.fetch` with credentials).** Less code, but whether a `SameSite=Strict` cookie is sent depends on how Chromium judges a request that comes from the main process, and a change in Electron could silently sign everyone out. The explicit jar is the same on every system and is unit-tested.
- **Change the API:** drop `SameSite=Strict` or add CORS for `app://nimbus`, or return the refresh token in the body. That weakens the browser's protection for everyone to suit one client.
- **Load the hosted web app in the window instead of the built files.** Needs a hosted Nimbus, which doesn't exist yet, and makes the app unusable offline from the first byte. This remains the likeliest way to get provider sign-in later.
