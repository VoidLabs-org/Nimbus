# Two-step verification has no way around it

A User can turn on Two-step verification on the Security page, so that signing in also needs a Sign-in code from an authenticator app (or one of their Recovery codes). Two choices here would surprise a reader who knows how many other apps do it, and both follow from one rule: once it is on, no way into the account works without the second step.

- **Google and GitHub sign-ins are asked too.** Many apps (Slack, Atlassian) skip their own second step after "Sign in with Google" and trust the provider. We ask for the Sign-in code after every sign-in, password or Linked identity alike, as Steam asks for Steam Guard on every sign-in. Nimbus can't see whether Google or GitHub used a second step, and a User who turned this on in Nimbus expects Nimbus to ask. Skipping it would let anyone who took over the User's Google account straight in, the same concern that made a disconnect stick ([ADR 0004](0004-connecting-and-disconnecting-linked-identities.md)).
- **A Reset code alone can't set a new password.** For a User with Two-step verification, forgot password also needs a Sign-in code or a Recovery code before the new password is set, as GitHub and Microsoft do. Turning Two-step verification off on reset would make the inbox the only factor again. Only asking at the next sign-in would still let someone with just the inbox change the password and end every Session, as often as they like. There is no emailed way to turn it off either: a User who has lost both their phone and their Recovery codes asks the team, who turn it off for them.

The cost is more steps for honest Users (a code after every Google sign-in, unless they ticked "Don't ask again on this device") and a manual recovery path that won't scale past a small team. Making it required for everyone, and an admin control for turning it off, are left for later.
